SECTION 3: ARCHITECTURE & DESIGN PATTERNS
================================================================================

1. COMPONENT-BASED ARCHITECTURE
--------------------------------
Concept: Break UI into small, reusable pieces (components)

Example:
- PageHeader component → Used in all pages
- SearchBar component → Used in dealers, vehicles, users pages
- ConfirmDialog component → Used for all delete confirmations

Benefits:
✓ Code reusability
✓ Easy to maintain
✓ Easy to test
✓ Consistent UI across app

2. CONTAINER/PRESENTATION PATTERN
----------------------------------
Concept: Separate data logic from UI rendering

Container Components (Smart):
- DealersPage.jsx → Fetches data, handles mutations
- VehiclesPage.jsx → Manages state, API calls

Presentation Components (Dumb):
- PageHeader.jsx → Just displays title and button
- SearchBar.jsx → Just displays search input
- ConfirmDialog.jsx → Just displays confirmation dialog

Benefits:
✓ Clear separation of concerns
✓ Easier to test
✓ More reusable components


3. STATE MANAGEMENT (3 TYPES)
------------------------------

A. SERVER STATE (TanStack Query)
   - What: Data from backend API
   - Examples: List of dealers, vehicles, users
   - Why TanStack Query: Automatic caching, refetching, loading states
   
   Code Example:
   const { data, isLoading } = useQuery({
     queryKey: ['dealers'],
     queryFn: () => dealerApi.getAll()
   });

B. GLOBAL STATE (Zustand)
   - What: Data shared across entire app
   - Examples: Logged-in user info, authentication token
   - Why Zustand: Simple, no boilerplate, persistent storage
   
   Code Example:
   const { user, token, login, logout } = useAuthStore();

C. LOCAL STATE (useState)
   - What: Component-specific data
   - Examples: Form inputs, dialog open/close, search text
   - Why useState: Built-in React hook, simple for local data
   
   Code Example:
   const [search, setSearch] = useState('');


4. ROUTING ARCHITECTURE
------------------------

Public Routes (No login required):
- /login → Login page
- /register → Registration page

Protected Routes (Login required):
- /dashboard → Dashboard (all roles)
- /dealers → Dealers list (ADMIN, DEALER, MANAGER)
- /vehicles → Vehicles list (all roles)
- /admin/users → User management (ADMIN, DEALER)
- /admin/roles → Role management (ADMIN only)
- /admin/menus → Menu management (ADMIN only)

Route Protection Logic:
1. Check if user is logged in (has token)
2. Check if user has required role
3. If not → Redirect to login or unauthorized page

Code Example (ProtectedRoute.jsx):
if (!token) return <Navigate to="/login" />;
if (!hasAnyRole(requiredRoles)) return <Navigate to="/unauthorized" />;
return <Outlet />; // Show the page


5. API LAYER ARCHITECTURE
--------------------------

Centralized API Configuration (axiosInstance.js):
- Base URL configuration
- Request interceptors (add JWT token to headers)
- Response interceptors (handle 401 errors, refresh token)
- Idempotency key generation for POST requests

API Modules (Organized by domain):
- dealerApi.js → All dealer endpoints
- vehicleApi.js → All vehicle endpoints
- userApi.js → All user endpoints
- authApi.js → Authentication endpoints
- roleApi.js → Role management endpoints
- menuApi.js → Menu management endpoints

Benefits:
✓ Single source of truth for API calls
✓ Easy to mock for testing
✓ Consistent error handling
✓ Automatic token management

Example Structure:
export const dealerApi = {
  getAll: (params) => axiosInstance.get('/v1/dealers', { params }),
  getById: (id) => axiosInstance.get(`/v1/dealers/${id}`),
  create: (data) => axiosInstance.post('/v1/dealers', data),
  update: (id, data) => axiosInstance.put(`/v1/dealers/${id}`, data),

FEATURE 1: SERVER-SIDE PAGINATION
----------------------------------
What: Load data page by page from server (not all at once)
Why: Better performance, handles large datasets

Implementation:
1. Track current page and page size in state
2. Send page/size params to backend
3. Backend returns: { content: [...], totalElements: 100 }
4. Display data with pagination controls

Code Flow:
const [paginationModel, setPaginationModel] = useState({ page: 0, pageSize: 10 });

useQuery({
  queryKey: ['dealers', paginationModel.page, paginationModel.pageSize],
  queryFn: () => dealerApi.getAll({
    page: paginationModel.page,
    size: paginationModel.pageSize
  })
});

<DataGrid
  paginationMode="server"
  paginationModel={paginationModel}
  onPaginationModelChange={setPaginationModel}
/>

Benefits:
✓ Fast initial load
✓ Handles millions of records
✓ Reduced memory usage


FEATURE 2: DEBOUNCED SEARCH
----------------------------
What: Wait for user to stop typing before searching
Why: Reduces API calls, better performance

Implementation:
1. User types in search box
2. If user clears input → Search immediately
3. If user types → Wait for Enter key
4. Send search query to backend

Code Flow:
const [search, setSearch] = useState('');

<SearchBar 
  onSearch={(value) => {
    setSearch(value);
    setPaginationModel(m => ({ ...m, page: 0 })); // Reset to first page
  }}
/>

useQuery({
  queryKey: ['dealers', search],
  queryFn: () => dealerApi.getAll({ search })
});

Benefits:
✓ Fewer API calls
✓ Better user experience
✓ Reduced server load


FEATURE 3: LINKED DROPDOWNS (CASCADING DROPDOWNS)
--------------------------------------------------
What: Dropdown options depend on previous selection
Example: Model → Variant → Color

Implementation Flow:
1. User selects Model (e.g., "Creta")
2. Fetch variants for "Creta" → ["SX", "EX", "SX(O)"]
3. User selects Variant (e.g., "SX")
4. Fetch colors for "Creta" + "SX" → ["White", "Black", "Red"]

Code Flow:
const watchModel = watch('model');
const watchVariant = watch('variant');

// Fetch variants when model changes
useQuery({
  queryKey: ['variants', watchModel],
  queryFn: () => vehicleApi.getVariants(watchModel),
  enabled: !!watchModel  // Only fetch if model is selected
});

// Fetch colors when model AND variant change
useQuery({
  queryKey: ['colors', watchModel, watchVariant],
  queryFn: () => vehicleApi.getColors(watchModel, watchVariant),
  enabled: !!watchModel && !!watchVariant
});

Benefits:
✓ Better user experience
✓ Data consistency
✓ Prevents invalid combinations


FEATURE 4: FORM VALIDATION (CLIENT-SIDE)
-----------------------------------------
What: Validate user input before sending to server
Why: Better UX, reduce server load, instant feedback

Two-Layer Validation:
1. React Hook Form → Manages form state, handles submission
2. Yup Schema → Defines validation rules

Example Validation Rules:
- Email: Must be valid email format
- Phone: Must be 10 digits
- VIN: Must be exactly 17 characters
- Password: Min 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special char

Code Example:
const schema = yup.object({
  email: yup.string().email('Invalid email').required('Email is required'),
  phone: yup.string().matches(/^\d{10}$/, 'Must be 10 digits'),
  vin: yup.string().length(17, 'VIN must be 17 characters')
});

const { register, handleSubmit, formState: { errors } } = useForm({
  resolver: yupResolver(schema)
});

<TextField 
  {...register('email')}
  error={!!errors.email}
  helperText={errors.email?.message}
/>

Benefits:
✓ Instant feedback to user
✓ Prevents invalid data submission
✓ Better user experience


FEATURE 5: OPTIMISTIC UPDATES
------------------------------
What: Update UI immediately, then sync with server
Why: Feels instant, better user experience

Example: Deleting a dealer
1. User clicks delete
2. Remove dealer from UI immediately
3. Send delete request to server
4. If success → Keep UI as is
5. If error → Restore dealer in UI, show error

Code Example:
const deleteMutation = useMutation({
  mutationFn: (id) => dealerApi.delete(id),
  onSuccess: () => {
    queryClient.invalidateQueries(['dealers']); // Refresh list
    notify.success('Dealer deleted');
  },
  onError: (error) => {
    queryClient.invalidateQueries(['dealers']); // Restore original data
    handleError(error);
  }
});

Benefits:
✓ Instant feedback
✓ Better perceived performance
✓ Handles errors gracefully


FEATURE 6: DRAG AND DROP (MENU REORDERING)
-------------------------------------------
What: Reorder menu items by dragging
Why: Intuitive UI, easy menu management

Implementation:
1. User drags menu item
2. Drop in new position
3. Update displayOrder for all affected items
4. Send batch update to backend

Code Flow:
const handleDragEnd = (result) => {
  if (!result.destination) return;
  
  const items = Array.from(menus);
  const [reorderedItem] = items.splice(result.source.index, 1);
  items.splice(result.destination.index, 0, reorderedItem);
  
  // Update displayOrder for all items
  const updates = items.map((item, index) => ({
    ...item,
    displayOrder: index
  }));
  
  // Send to backend
  updateMenuOrder(updates);
};

Benefits:
✓ Intuitive user interface
✓ No manual order input needed
✓ Visual feedback during drag

SECTION 6: SECURITY IMPLEMENTATION
================================================================================

1. AUTHENTICATION
-----------------
Mechanism: JWT (JSON Web Token)

Flow:
1. User logs in with username/password
2. Backend validates and returns JWT token
3. Frontend stores token in localStorage
4. Token included in all API requests (Authorization header)
5. Token expires after 24 hours
6. Refresh token used to get new access token

Code:
// Login
const response = await authApi.login({ username, password });
const { token, refreshToken, user } = response.data.data;
localStorage.setItem('token', token);
localStorage.setItem('refreshToken', refreshToken);

// Add token to requests
axios.interceptors.request.use(config => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});


2. AUTHORIZATION
----------------
Mechanism: Role-Based Access Control (RBAC)

Implementation:
- Frontend checks user roles before showing UI
- Backend validates roles before executing actions
- Protected routes redirect unauthorized users

Code:
const hasRole = (role) => user?.roles?.includes(role);
const hasAnyRole = (roles) => roles.some(role => hasRole(role));

if (!hasAnyRole(['ADMIN', 'DEALER'])) {
  return <Navigate to="/unauthorized" />;
}

3. TOKEN REFRESH
----------------
What: Automatically refresh expired tokens
Why: Better UX, no forced logout

Flow:
1. API call returns 401 (Unauthorized)
2. Interceptor catches error
3. Try to refresh token
4. If success → Retry original request
5. If fail → Logout user

Code:
axios.interceptors.response.use(
  response => response,
  async error => {
    if (error.response?.status === 401) {
      const refreshToken = localStorage.getItem('refreshToken');
      const newToken = await authApi.refresh(refreshToken);
      localStorage.setItem('token', newToken);
      return axios(error.config); // Retry original request
    }
  }
);


4. ACCOUNT LOCKING
------------------
What: Lock account after 5 failed login attempts
Why: Prevent brute force attacks

Implementation:
- Backend tracks failed login attempts
- After 5 failures → accountLocked = true
- Admin/Dealer can unlock via "Unlock Account" button

Code:
{row.accountLocked && (
  <IconButton onClick={() => unlockMutation.mutate(row.id)}>
    <LockOpen />

)}

5. IDEMPOTENCY
--------------
What: Prevent duplicate operations from multiple clicks
Why: Data consistency, prevent duplicate records

Implementation:
- Generate unique key for each POST request
- Backend checks if key already processed
- If yes → Return cached response
- If no → Process request

Code:
axios.interceptors.request.use(config => {
  if (config.method === 'post') {
    config.headers['X-Idempotency-Key'] = generateUUID();
  }
  return config;
});

2. CACHING STRATEGY

Cache Configuration:

- cacheTime: 10 minutes (cache kept in memory)
- refetchOnWindowFocus: true (refresh when user returns)

Benefits:
✓ Instant data display from cache
✓ Background updates
✓ Reduced API calls


3. OPTIMIZED RE-RENDERS
------------------------
Problem: React re-renders components when state changes
Solution: Minimize unnecessary re-renders

Techniques Used:
- React Hook Form: Uncontrolled inputs (fewer re-renders)
- TanStack Query: Separate server state from component state
- Zustand: Selective subscriptions
- useMemo: Cache expensive calculations

Example:
// Without useMemo (recalculates every render)
const total = items.reduce((sum, item) => sum + item.price, 0);

// With useMemo (recalculates only when items change)
const total = useMemo(
  () => items.reduce((sum, item) => sum + item.price, 0),
  [items]
);

ARCHITECTURE QUESTIONS

Q1: Why did you choose React over Angular or Vue?
A: React has:
   - Larger ecosystem and community
   - Better performance with Virtual DOM
   - More job opportunities (industry standard)
   - Easier learning curve
   - Better integration with modern tools

Q2: Why Vite instead of Create React App?
A: Vite is:
   - 10-100x faster in development
   - Instant Hot Module Replacement (HMR)
   - Smaller bundle size
   - Better developer experience
   - Modern tooling (ESBuild, Rollup)

Q3: Why TanStack Query instead of Redux?
A: TanStack Query is:
   - Designed specifically for server state
   - Automatic caching and refetching
   - Less boilerplate code
   - Built-in loading/error states
   - Better for API-heavy apps
   Redux is for complex client state, which we don't have much of.


Q4: Why Zustand instead of Redux or Context API?
A: Zustand is:
   - Simpler API (less boilerplate)
   - Better performance than Context API
   - Smaller bundle size than Redux
   - Built-in persistence
   - Perfect for our simple global state needs

Q5: Explain the folder structure
A: Organized by feature and type:
   - /api → All API calls (organized by domain)
   - /components → Reusable UI components
   - /pages → Full page components
   - /hooks → Custom React hooks
   - /store → Global state management
   - /router → Routing configuration
   Benefits: Easy to find files, scalable, maintainable

Q6: How do you handle state management?
A: Three-tier approach:
   1. Server State (TanStack Query) → API data
   2. Global State (Zustand) → Auth, user info
   3. Local State (useState) → Component-specific data
   Each tool for its specific purpose.


IMPLEMENTATION QUESTIONS
------------------------

Q7: How does pagination work?
A: Server-side pagination:
   1. Frontend sends page number and size to backend
   2. Backend returns: { content: [...], totalElements: 100 }
   3. DataGrid displays current page
   4. User clicks next → Fetch next page
   Benefits: Fast, handles large datasets, reduced memory

Q8: How does search work?
A: Debounced search:
   1. User types in search box
   2. Wait for Enter key (debouncing)
   3. Send search query to backend
   4. Backend searches in database
   5. Return filtered results
   Benefits: Fewer API calls, better performance

Q9: Explain linked dropdowns implementation
A: Cascading dropdowns (Model → Variant → Color):
   1. User selects Model
   2. Fetch variants for that model
   3. Enable variant dropdown
   4. User selects Variant
   5. Fetch colors for model+variant
   6. Enable color dropdown
   Uses React Hook Form's watch() to track changes.


Q10: How do you handle form validation?
A: Two-layer validation:
   1. Client-side (React Hook Form + Yup):
      - Instant feedback
      - Prevents invalid submission
      - Better UX
   2. Server-side (Jakarta Validation):
      - Security layer
      - Handles edge cases
      - Final validation
   Both layers ensure data integrity.

Q11: How do you handle errors?
A: Centralized error handling:
   1. API error occurs
   2. Axios interceptor catches it
   3. useApiError hook extracts message
   4. Display toast notification
   5. Log error for debugging
   Benefits: Consistent error messages, easy to maintain

Q12: How does authentication work?
A: JWT-based authentication:
   1. User logs in
   2. Backend returns JWT token
   3. Store token in localStorage
   4. Add token to all API requests (Authorization header)
   5. Backend validates token
   6. If expired → Refresh token
   7. If invalid → Logout


Q13: How does role-based access control work?
A: Three-level protection:
   1. Route Level: ProtectedRoute checks roles before rendering
   2. Component Level: Conditional rendering based on roles
   3. API Level: Backend validates roles (final security)
   Example: Only ADMIN can access /admin/roles

Q14: How do you prevent duplicate submissions?
A: Idempotency implementation:
   1. Generate unique key for each POST request
   2. Send key in X-Idempotency-Key header
   3. Backend checks if key already processed
   4. If yes → Return cached response
   5. If no → Process request
   Prevents duplicate records from double-clicks.

Q15: How does drag-and-drop work?
A: HTML5 Drag and Drop API:
   1. User drags menu item
   2. onDragStart → Store dragged item
   3. onDragOver → Show drop indicator
   4. onDrop → Update order
   5. Send new order to backend
   Native implementation, no external library needed.


PERFORMANCE QUESTIONS

Q16: How do you optimize performance?
A: Multiple strategies:
   - Code splitting (lazy loading)
   - Caching (TanStack Query)
   - Debouncing (search)
   - Pagination (load in chunks)
   - Memoization (useMemo, useCallback)
   - Optimized re-renders (React Hook Form)
   - Bundle optimization (tree shaking, minification)

Q17: What is code splitting and how does it help?
A: Load code only when needed:
   - Initial load: Only load login page
   - Navigate to dealers → Load dealers page
   - Navigate to vehicles → Load vehicles page
   Benefits: Faster initial load, smaller bundle

Q18: How does caching work?
A: TanStack Query automatic caching:
   - First request → Fetch from server, cache response
   - Subsequent requests → Return from cache instantly
   - Background refetch → Update cache silently
   - Stale time: 5 minutes
   Benefits: Instant data display, reduced API calls


Q19: How do you handle large datasets?
A: Server-side pagination:
   - Load 10-50 records at a time
   - User navigates pages → Load next chunk
   - Never load all data at once
   Can handle millions of records efficiently.

Q20: What is debouncing and why use it?
A: Wait for user to stop typing before searching:
   - User types "Hyundai"
   - Without debouncing: 7 API calls (H, Hy, Hyu, ...)
   - With debouncing: 1 API call (after Enter key)
   Benefits: Fewer API calls, better performance

SECURITY QUESTIONS
------------------

Q21: How do you secure the application?
A: Multiple layers:
   - Authentication (JWT tokens)
   - Authorization (role-based access)
   - Token refresh (automatic)
   - Account locking (5 failed attempts)
   - Idempotency (prevent duplicates)
   - XSS protection (React escaping)
   - HTTPS (production)


Q22: How do you prevent XSS attacks?
A: React's built-in protection:
   - All user input automatically escaped
   - HTML tags rendered as text, not executed
   - Never use dangerouslySetInnerHTML
   - Sanitize any external content

Q23: How do you handle token expiration?
A: Automatic token refresh:
   1. API call returns 401 (token expired)
   2. Interceptor catches error
   3. Try to refresh token using refresh token
   4. If success → Retry original request
   5. If fail → Logout user
   User never sees "session expired" unless refresh fails.

Q24: Where do you store tokens?
A: localStorage (not cookies):
   - Pros: Easy to access, works across tabs
   - Cons: Vulnerable to XSS (mitigated by React)
   - Alternative: httpOnly cookies (more secure but complex)
   For this app, localStorage is acceptable.

Q25: How do you prevent CSRF attacks?
A: JWT in headers (not cookies):
   - Tokens sent in Authorization header
   - Not automatically sent by browser
   - Cannot be exploited by malicious sites
   CSRF only affects cookie-based auth.

TECHNICAL QUESTIONS
-------------------

Q35: What is Virtual DOM and how does it work?
A: React's optimization technique:
   1. Create virtual copy of DOM in memory
   2. When state changes → Update virtual DOM
   3. Compare with previous virtual DOM (diffing)
   4. Update only changed parts in real DOM
   Benefits: Faster updates, better performance


Q36: What are React Hooks?
A: Functions that let you use React features:
   - useState → Manage component state
   - useEffect → Side effects (API calls, subscriptions)
   - useQuery → Fetch data (TanStack Query)
   - useMutation → Modify data (TanStack Query)
   - Custom hooks → Reusable logic (useNotify, useApiError)

Q37: What is the difference between useEffect and useQuery?
A: Different purposes:
   useEffect:
   - General side effects
   - Manual data fetching
   - Subscriptions, timers
   
   useQuery:
   - Specifically for data fetching
   - Automatic caching
   - Loading/error states
   - Background refetching
   
   Use useQuery for API calls, useEffect for other side effects.

Q38: What is prop drilling and how do you avoid it?
A: Passing props through many levels:
   Problem: App → Page → Container → Component (4 levels)
   
   Solutions:
   1. Context API (for theme, auth)
   2. Zustand (for global state)
   3. TanStack Query (for server state)
   
   We use all three to avoid prop drilling.


Q39: What is the difference between controlled and uncontrolled components?
A: Form input handling:
   
   Controlled (React Hook Form):
   - React controls the input value
   - Value stored in state
   - onChange updates state
   - Better for validation
   
   Uncontrolled (refs):
   - DOM controls the input value
   - Access via ref
   - Less re-renders
   - Better performance
   
   We use React Hook Form (uncontrolled) for better performance.

Q40: What is memoization?
A: Cache expensive calculations:
   
   useMemo:
   - Cache calculation result
   - Recalculate only when dependencies change
   
   useCallback:
   - Cache function reference
   - Prevent unnecessary re-renders
   
   Example:
   const total = useMemo(() => 
     items.reduce((sum, item) => sum + item.price, 0),
     [items]
   );
